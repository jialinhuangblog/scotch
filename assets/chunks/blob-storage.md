# Blob Storage

> 使用者上傳的圖片、影片、備份檔，總不會一股腦塞進資料庫吧？

## 用 key 存大檔案

blob storage（物件儲存）專門放大的、非結構化的檔案：圖片、影片、備份。S3、GCS、Azure Blob 是代表。

檔案存成「物件」丟進 bucket，用一個 key 透過 HTTP 存取，不走 DB。常見做法是 DB 只存物件的 URL 跟 metadata，檔案本體放 blob storage，前面再接 CDN 分發。

它不是檔案系統：沒有真的資料夾，是一個扁平的 key 空間（用 `/` 當前綴，讓 key 看起來像目錄）。物件不可變，要改就整個覆蓋，不能改一半。

像一個超大寄物櫃：每個櫃子一個號碼牌（key），放大件行李很便宜也很耐放，但每天要翻好幾次的小東西不會放在這裡。

## 為什麼這麼耐放

背後用 erasure coding：把資料切成片、再算一些冗餘碼一起分散存，少數磁碟壞掉也能從其他片還原。所以耐久度極高，S3 標稱 11 個 9（一年弄丟一個物件的機率小到可以忽略）。

代價是單個物件的存取延遲比 DB 高，也沒有部分更新，所以不適合高頻交易型資料，適合圖片、影片、備份這類寫一次、讀很多、不常改的資料。
