# Lamport Clock

分散式系統判斷「誰先誰後」不能靠牆上時鐘，因為每台機器的[時鐘不同步](chunk://clocks)。Lamport clock 乾脆不用時間，用遞增的計數器。

先講計數器長什麼樣。每個節點手上一個整數，從 0 開始。它只在兩種時候動：自己做了一件事（寫一筆、送一則訊息），+1；收到別人的訊息，訊息裡夾著對方當時的數字，拿來跟自己的比，取大的那個再 +1。

拿兩台機器走一遍。A 連做三件事，計數器 1、2、3。第三件就是送一則訊息給 B，因為送出本身也算一件事，+1 之後是 3，訊息上標的就是這個 3。B 這段時間自己做了兩件事，計數器 1、2。訊息到了，B 看一眼：對方 3、自己 2，取 3 再 +1，B 的計數器跳到 4。

```text
Node A:  1 → 2 → 3
                    ↘ 訊息帶著 3 送給 B
Node B:        1 → 2 → max(2, 3) + 1 = 4
```

為什麼要取 max，不是直接 +1 就好？B 收到訊息時要是只 +1，會變 3，跟 A 送出時的 3 一樣大。但「B 收到」明明發生在「A 送出」之後，數字應該要更大才對。取 max 就是把對方走過的路算進來：A 已經走到 3 了，B 接在後面，至少得是 4。

所以這個數字保證的是：只要 A 事件真的影響了 B 事件（A 送訊息、B 收到，或是同一台機器上 A 先做），A 的數字一定比 B 小。

反過來不成立。B 自己做的第二件事是 2，A 送訊息那一步是 3，2 比 3 小，但這兩件事互不相干，誰先誰後根本沒意義。計數器小只代表「可能在前面」，不代表真的在前面。要分辨兩個事件是有因果關係還是同時發生，得用 [Vector Clock](chunk://vector-clock)。
